# Build-Authoring Documentation Map

This folder contains build authoring workflow, prompt guidance, and the
`BuildMgr`/`SkillsTemplate` contract.

## Authority and status

- `buildmgr-and-skills-template.md` describes the current ownership and package
  contract between `BuildMgr`, `SkillsTemplate`, and skill modules.
- [Smart Spirit Transfer](smart-spirit-transfer.md) records the Stage 1 owner-local
  extraction, historical stock admission changes, and offline verification boundary.
- [Smart Spirit Light](smart-spirit-light.md) records the genuine-spirit-only My BiP
  extraction and the historical stock sacrifice-fallback consequences.
- [Smart Kaolai extraction](smart-kaolai-extraction.md) preserves the historical
  extraction and generic release restoration, with a dated reconciliation of
  current ownership, flexible matching, adaptive release, and Option A.
- [Smart Kaolai observation](smart-kaolai-observation.md) preserves the historical
  missed-drop investigation, capture evidence, and superseded tactical proposal;
  it distinguishes those findings from completed behavior and accepted limits.
- `build-authoring-handover.md` records the preferred implementation method:
  thin explicit build controllers with generic behavior owned by `BuildMgr`.
- `build-prompting-guide.md` records an effective request shape for build work;
  it is workflow guidance, not runtime behavior.
- Current `Py4GWCoreLib/BuildMgr.py`, `Py4GWCoreLib/Builds/Skills/`, HeroAI
  skill metadata, and active build scripts outrank examples or recommendations
  in these documents.

## Review order

1. Read the ownership contract.
2. Read the handover for implementation boundaries.
3. Use the prompting guide to structure a request or analysis.
4. Inspect the affected build, `BuildMgr`, skill metadata, and current fallback
   behavior before editing.
